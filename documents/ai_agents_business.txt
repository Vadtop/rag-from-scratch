AI-агенты для автоматизации бизнеса

AI-агент — это автономная система, которая воспринимает окружение, принимает решения и выполняет действия для достижения цели без постоянного участия человека.

Типы AI-агентов в бизнесе:
1. Агент поддержки клиентов — отвечает на FAQ, маршрутизирует тикеты, эскалирует сложные случаи
2. Агент продаж — квалифицирует лиды, назначает демо, ведёт follow-up автоматически
3. Агент аналитики — мониторит KPI, генерирует отчёты, выявляет аномалии
4. Агент маркетинга — управляет кампаниями, A/B тестами, сегментацией аудитории
5. Агент CRM — обновляет записи, логирует взаимодействия, синхронизирует данные

Ключевые компоненты AI-агента:
- LLM ядро: GPT-4, Claude, Gemini, DeepSeek — для рассуждений и генерации
- Память: краткосрочная (история диалога) + долгосрочная (векторная БД: ChromaDB, Pinecone)
- Инструменты: веб-поиск, вызовы API, запросы к БД, отправка email
- RAG (Retrieval-Augmented Generation): агент ищет в базе знаний перед ответом
- Оркестрация: LangChain, CrewAI, AutoGen для мультиагентных сценариев

Архитектура RAG:
RAG сочетает поиск с генерацией. Когда пользователь задаёт вопрос:
1. Вопрос преобразуется в вектор (embedding)
2. Похожие векторы извлекаются из векторной базы данных
3. Найденный контекст добавляется в промпт LLM
4. LLM генерирует ответ на основе реальных данных, а не из головы

Это предотвращает галлюцинации и делает ответы точными и актуальными.

Оптимизация стоимости LLM:
- Использовать дешёвые модели (DeepSeek, GPT-3.5) для простых задач, дорогие (GPT-4, Claude) для сложных
- Кешировать частые запросы через семантическое сходство
- Ограничивать контекст — отправлять только релевантные чанки, не весь документ
- Батчевать запросы там где возможно
- Мониторить расход токенов по пользователям и функциям

Оптимизация латентности:
- Стримить ответы вместо ожидания полного завершения
- Использовать лёгкие модели для эмбеддингов
- Предвычислять эмбеддинги для статичной базы знаний
- Использовать async/параллельные вызовы для независимых операций

Примеры автоматизаций в n8n:
- Триггер: новый лид в CRM → агент квалифицирует → обновляет CRM + отправляет email
- Триггер: тикет поддержки → агент классифицирует и маршрутизирует → уведомляет команду в Slack
- Триггер: расписание → агент парсит цены конкурентов → обновляет таблицу
- Триггер: вебхук от платёжной системы → агент отправляет персонализированный онбординг

Интеграция с CRM (amoCRM, Bitrix24):
- Подключение через REST API с OAuth2 аутентификацией
- Вебхуки для обработки событий в реальном времени
- Типичные операции: создание/обновление контактов, сделок, задач
- AI-агент может составлять ответы, классифицировать лиды, прогнозировать отток

Google Sheets как простая база данных:
- Библиотека gspread на Python с учётными данными Service Account
- Запись строк для логирования: запросы, ответы, временные метки
- Чтение данных для простых баз знаний или конфигурации
- Удобно для нетехнических сотрудников — просматривают логи агента

Паттерны памяти агента:
- Window memory: хранить последние N сообщений в контексте
- Summary memory: сжимать старую историю через LLM
- Entity memory: извлекать и хранить ключевые сущности (имена, даты, факты)
- Vector memory: семантический поиск по прошлым разговорам

Бизнес-метрики AI-агентов:
- Точность ответов (оценка человеком или LLM-as-judge)
- Средняя латентность (цель: менее 3 секунд)
- Стоимость запроса (токены × цена за токен)
- Процент эскалаций (% запросов, которые агент не смог обработать)
- Оценка удовлетворённости пользователей

Типичные ошибки:
- Галлюцинации: агент выдумывает факты → исправление через RAG + валидацию выходных данных
- Переполнение контекста: слишком много истории в промпте → исправление через суммаризацию или векторную память
- Злоупотребление инструментами: агент вызывает tools без необходимости → исправление через чёткие описания инструментов
- Prompt injection: пользователь пытается переопределить системный промпт → исправление через санитизацию входных данных
